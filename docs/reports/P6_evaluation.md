### P7 への申し送り（重要）

1. **作業ツリーは CRLF、index は LF。** `core.autocrlf=true` かつ `.gitattributes` なし。
   `03_database.md` §7 の書式要件は index 上で満たされているが、チェックアウト後のファイルは CRLF になる。
   → **T-705 の `check-drift` はバイト比較をしてはならない。** パース結果の比較か、改行正規化後の比較にすること。
   Python が `newline="\n"` で書き出すと、毎回ディスク上の CRLF と差分が出て偽陽性になる。
2. `JSON.stringify(obj, null, 2) + "\n"`（今回使用）と `json.dump(indent=2, ensure_ascii=False)` は、
   本データにおいて**バイト一致**する。`winRate: 52.4` を削除した結果、残る数値がすべて整数になり、
   Python の `1.0` / JS の `1` という浮動小数表記の差異も発生しない。
3. `09_data_pipeline.md` §4-D の統計混入検査（`/[%％]|勝率|ピック率/`）は
   **`data/matchups/` 配下のみを対象にすること。** UI文言には「統計上の勝率ではありません」という
   打ち消し文が意図的に含まれるため、リポジトリ全体に掛けると誤検知する。
   なお `data/` 側の `%` は `HP60%以下` のような本文中の表現として実在するため、
   `%` 単体での機械検出は使えない（「勝率」「ピック率」等の語との併用で判定すること）。
4. `data/champions.json` / `glossary.json` は畳んだままにしてある。§7 の対象は
   パイプラインが生成する `data/matchups/` に限られるため、意図的に正規化していない。
