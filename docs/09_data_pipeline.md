# Weekly Data Pipeline Design

> **MVPでは設計のみ。実装しない。** MVPは手作りモックデータ（[03_database.md](./03_database.md) §6）で公開する。
> 本書は 01_requirements §9「データ更新」の詳細設計であり、実装は将来フェーズで行う。

## 1. 全体フロー

毎週（パッチ適用後）に実行し、`data/` 更新PRを自動作成する。実行環境は `scripts/`（ローカル実行 or GitHub Actions）。

```
1. 統計取得      パッチ後の対面統計を取得（方式TBD、§2）
2. 差分抽出      前回データと比較し、更新が必要な対面のみ抽出（生成コスト削減）
3. AI生成        統計を入力にLLMがアドバイスJSONを生成（§3）
4. 自動検証      スキーマ・内容の機械チェック（§4）
5. PR作成        data/{patch} ブランチでPR自動作成
6. 人手レビュー   Vercel Previewで表示確認・内容レビュー
7. 本番反映      mainマージ → 再ビルド → タグ data/{patch} 付与
```

5〜7は [07_release.md](./07_release.md) §4 のリリースフローに乗せる。

## 2. 統計取得（TBD: 技術調査事項）

取得方式は未決（01_requirements §12）。候補:

| 候補 | 概要 | 論点 |
|---|---|---|
| Riot API から自前集計 | Match-V5 で対戦データを収集し対面勝率を集計 | 収集量・レート制限・集計基盤が必要。BOT 2v2ペア統計も自前で作れる |
| サードパーティ統計の参照 | 既存統計サイトのデータ | 利用規約・ライセンス確認が必須 |
| ハイブリッド | 通常レーンは外部、BOTペアは自前集計 | BOT(4体)統計は既存サービスに少ないため現実解になり得る |

調査完了後、本節を確定させる。

## 3. AI生成

- **LLM: 未定（TBD）**。選定時にコスト・日本語品質・構造化出力の安定性で比較する
- 入力: 対面の統計値 + チャンピオン基礎情報（スキル・ロール） / 出力: [03_database.md](./03_database.md) §3 のJSONスキーマに完全準拠
- プロンプト設計方針:
  - ターゲット（ゴールド〜プラチナ、初心者〜中級者）に合わせた平易な日本語
  - 有利不利（aiRating）は統計とチャンピオン知識の総合判断としてLLMに判定させる（01_requirements §5）
  - 要約は「30秒で読める」長さ、立ち回りは序盤/中盤/終盤の3分割を強制
  - 用語は `glossary.json` にある語のみ `glossaryRefs` に入れる
- **生成方式はユーザーへ公開しない**（PRD §6）。プロンプト・生成ロジックを公開リポジトリに置かないこと。**本リポジトリはprivate運用を前提とする**（publicにする場合は `scripts/` とプロンプトを分離する）

## 4. 自動検証

PR作成前に機械チェックで足切りする。

| 種別 | 内容 |
|---|---|
| スキーマ検証 | 型・必須項目・aiRating範囲(1〜5)・SpikeMark(◎○△) |
| 参照整合 | champion id / glossary slug / Data Dragonアイテム・スキル画像の実在 |
| 文字数 | 要約・立ち回り各節の上限下限（30秒要約が長文化しないように） |
| 表記 | NGワード・敬体常体の統一・数値と統計の矛盾（勝率0〜100%等） |

検証失敗した対面はPRから除外し、レポートに残す。

## 5. コスト管理の枠組み

LLM未定のため変数で管理する。選定時に確定し [10_operations.md](./10_operations.md) の管理表へ反映。

```
週次生成コスト ≒ 更新対面数 × (入力トークン + 出力トークン) × 単価
```

- 差分抽出（§1-2）で更新対面数を絞ることが最大のコストレバー
- 累積赤字5万円以内（PRD §3）を超えない範囲で対面カバレッジを段階拡大する
- 生成対象の優先順位: ピック率の高い対面から

## 6. 段階導入計画

| 段階 | 内容 |
|---|---|
| MVP | モックデータのみ（本パイプラインなし） |
| Phase 1 | 統計取得方式の確定・LLM選定・少数対面で試験生成 |
| Phase 2 | 週次自動実行（人手レビューは継続） |
| Phase 3 | カバレッジ拡大・リアルタイムAI検討（PRD §7） |
