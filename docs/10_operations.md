# Operations

## 1. 週次運用サイクル

LoLのパッチ適用（約2週間ごと）と週次更新（01_requirements §9）に合わせて運用する。

| タイミング | 作業 |
|---|---|
| パッチ適用後 | データ更新（[09_data_pipeline.md](./09_data_pipeline.md) §1 の Phase 1 CLI 手順で実施。`DDRAGON_VERSION` 更新 → `ddragon sync` / `champions sync` → `validate --all` → `data/{patch}` PR） |
| PR作成後 | Vercel Preview確認・内容レビュー・マージ（[07_release.md](./07_release.md) §4） |
| マージ後 | 本番表示確認（代表対面1件 + パッチバッジ表記）・タグ付与・古いタグ整理（直近4パッチ） |
| 随時 | Data Dragonバージョン追従（新チャンピオン・アイテム画像） |

## 2. コスト・収益管理

ビジネス目標（PRD §3）: 2027年1月までに月間利益3万円 / 新規追加費用の累積赤字5万円以内。

- 月次で管理表を記録する（リポジトリ外のスプレッドシート等でよい）:

| 項目 | 内容 |
|---|---|
| 支出 | Vercel Pro（$20/月・利用クレジット$20同梱）・ドメイン更新費・LLM API料金（将来）・従量課金（クレジット超過時） |
| 収入 | 広告収入（将来）・課金収入（将来） |
| 累積 | 累積収支（−5万円が撤退・見直しライン） |

- MVP時点の固定費は Vercel Pro の月額 + ドメイン代（DBなし・LLM未使用）。Pro の従量課金は席代同梱の$20クレジットで相殺され、この規模では実質$20/月に収まる見込み
- Vercel ダッシュボードの `Usage` タブで従量消費（Edge Requests・データ転送・Function・画像変換）とクレジット残を月次で確認し、超過見込みが出たら対策（画像最適化・ビルド頻度）を先に打つ
- 想定外の急増に備え、Spend Management のオンデマンド予算（既定$200・変更可）を設定しておく

## 3. 監視・計測

| 対象 | 手段 |
|---|---|
| 死活・エラー | Vercelダッシュボード（デプロイ失敗・Function エラー） |
| アクセス | Vercel Web Analytics（Proに一定イベント数含む・超過は従量）または Cloudflare 側の統計 |
| SEO | Google Search Console（sitemap登録・インデックス状況・検索流入） |
| 成功指標 | 週次でPV・検索流入・利用対面ランキングを確認し、モック→実データ拡大の優先順位に反映 |

## 4. 障害対応

| 事象 | 対応 |
|---|---|
| 本番表示崩れ・不具合 | Vercel Instant Rollback（[07_release.md](./07_release.md) §5）→ 原因調査 |
| データ内容の誤り | 該当データの `git revert` PR |
| Data Dragon 画像切れ | `lib/ddragon.ts` のバージョン定数を更新 |
| ドメイン/DNS障害 | Cloudflareダッシュボードでレコード・ステータスを確認 |

## 5. 定期見直し

- 月次: コスト管理表・成功指標・SEO状況のレビュー
- パッチ毎: データ鮮度（フッターの更新日表記）が2パッチ以上遅れていないこと
- 四半期: 将来機能（広告・課金・リアルタイムAI）の着手判断（PRD §7）
