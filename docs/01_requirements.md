# 01_requirements.md

# Functional Requirements

## 1. 目的

本書は Metaたろうの機能要件を定義する。

## 2. 対象ユーザー

-   日本サーバー
-   ゴールド〜プラチナ
-   ソロ/デュオ
-   ノーマルドラフト

## 3. 機能一覧

  ID       機能
  -------- ------------------------
  FR-001   通常レーン対面検索
  FR-002   BOTレーン(4体)対面検索
  FR-003   AIアドバイス表示
  FR-004   勝率表示（Phase 2以降。初版では非表示）
  FR-005   有利不利表示(5段階)
  FR-006   注意スキル表示
  FR-007   パワースパイク表示
  FR-008   推奨ルーン表示
  FR-009   推奨サモナースペル表示
  FR-010   推奨ビルド表示
  FR-011   検索履歴保存
  FR-012   SEOページ生成
  FR-013   データなし表示
  FR-014   週次データ更新

## 4. 検索

### 通常レーン

入力 - レーン - 自チャンピオン - 敵チャンピオン

### BOT

入力 - 自ADC - 自SUPPORT - 敵ADC - 敵SUPPORT

4体確定後のみ検索可能。

## 5. AIアドバイス

表示内容 - AI総合評価(5段階) - 30秒要約 - 詳細立ち回り -
注意スキル - パワースパイク - 推奨ルーン - 推奨サモナースペル -
推奨ビルド

有利不利はAIが総合判断する。

- **Phase 1（初版）**: 統計データを持たないため、チャンピオンの構成・スキル相性のみで判定する。勝率は表示しない
- **Phase 2以降**: 統計情報をAIへの入力に加え、勝率表示を復活させる（09_data_pipeline.md §2・§6）

## 6. データなし

十分な統計データが存在しない場合は 「データがありません」 を表示する。

## 7. 検索履歴

-   ローカルストレージ保存
-   直近10件

## 8. SEO

-   通常レーンページ
-   BOTページ
-   データなしページはnoindex

## 9. データ更新

パッチ適用後に実施。**更新頻度はPhase 1の運用実績を見て確定する**（当初想定は毎週）。

フロー（目標形。Phase 1 では 1・2 を行わず、対象はキューで人が管理する）
 1. データ取得 ← Phase 2以降
 2. 差分抽出 ← Phase 2以降
 3. AI生成 
 4. 自動検証 
 5. Pull Request 
 6. 人手レビュー 
 7. 本番反映

直近4バージョン保持。詳細は 09_data_pipeline.md。

## 10. 管理

管理はGitHub Pull Requestを利用する。

-   Vercel Preview確認
-   承認
-   公開
-   ロールバック
