## 4. 検索

### 通常レーン

入力 - レーン - 自チャンピオン - 敵チャンピオン

レーンは TOP / JG / MID / ADC / SUP の5択を表示するが、**選択できるのは TOP / MID のみ**。
残りは「準備中」として `disabled` で見せる（対応範囲を隠さず、将来の拡張を示すため）。

### BOT（当面スコープ外）

入力 - 自ADC - 自SUPPORT - 敵ADC - 敵SUPPORT / 4体確定後のみ検索可能。

仕様は [06_ui.md](./06_ui.md) §8 と [09_data_pipeline.md](./09_data_pipeline.md) §9 のアーカイブに退避。

## 5. AIアドバイス

表示内容 - AI総合評価(5段階) - 30秒要約 - 詳細立ち回り -
注意スキル - パワースパイク - 推奨ルーン - 推奨サモナースペル -
推奨ビルド

有利不利はAIが総合判断する。

- **Phase 1（初版）**: 統計データを持たないため、チャンピオンの構成・スキル相性のみで判定する。勝率は表示しない
- **Phase 2以降**: 統計情報をAIへの入力に加え、勝率表示を復活させる（09_data_pipeline.md §2・§6）。
  採否は T-1308 の判断ゲートで決める

**表示項目は P13 の T-1301 で見直す。** 「ユーザーが本当に欲しい情報は何か」を起点に、
不要な項目の削除と不足項目の追加を検討し、結論を UI（T-1403 / T-1404）と生成スキーマの双方へ反映する。

## 6. データなし

十分な統計データが存在しない場合は 「データがありません」 を表示する。

## 9. データ更新

パッチ適用後に実施。**更新頻度はPhase 1の運用実績を見て確定する**（当初想定は毎週）。

フロー（目標形。Phase 1 では 1・2 を行わず、対象はキューで人が管理する）
 1. データ取得 ← Phase 2以降
 2. 差分抽出 ← Phase 2以降
 3. AI生成 
 4. 自動検証 
 5. Pull Request 
 6. 人手レビュー 
 7. 本番反映

直近4バージョン保持。詳細は 09_data_pipeline.md。
