# Testing & Evaluation

## 1. 戦略

| 層 | 手段 | 対象 |
|---|---|---|
| 静的検査 | `npm run lint` / `npm run build` | 全コード。buildで全SSGページ生成が成功すること |
| ユニット | 最小限 | `lib/` のデータアクセス・slug変換・チャンピオン検索 |
| **画面評価（中心）** | **Playwright MCP** | 全画面の機能・プロトタイプとのUI/UX一致 |

## 2. Playwright MCP 評価手順

1. `npm run dev` でローカル起動（`http://localhost:3000`）
2. Playwright MCPでブラウザを開き、ビューポートを設定して各画面を巡回
   - モバイル: **390×844**（プロトタイプ 1a 基準）
   - PC: **1280×800**（プロトタイプ 2a 基準）
   - 参考: 768〜1279px で2カラム圧縮になることを1画面で確認
3. §4 のチェックリストを上から実行し、スクリーンショットを取得
4. 視覚照合: プロトタイプ `docs/design/LoL対面AIアドバイス Metaたろう プロトタイプ.dc.html` をブラウザで開き、対応する `data-screen-label` の画面と見比べる（[06_ui.md](./06_ui.md) §1 の対応表）

## 3. 評価用データ

モックデータ（[03_database.md](./03_database.md) §6）を使用する。

- 通常レーン代表: MID `ahri-vs-annie`（プロトタイプと同一対面）
- BOT代表: `jinx-thresh-vs-caitlyn-lulu`（同上）
- データなし代表: MID `yasuo-vs-zed`（意図的に未作成）

## 5. 手動確認（Playwrightで再現できない項目）

### IME（Windows日本語入力）

Playwright は文字を直接入力するためOSのIMEを経由せず、§4「「あに」→ アニー/アニビア」は
IMEが壊れていてもパスし続ける。**以下は実際にIMEで入力して目視確認する**（06_ui §6.1）。

- [ ] MS-IMEで「あに」を入力中（未確定の状態）、候補ドロップダウンが表示されないこと
- [ ] 変換確定のEnterでチャンピオンが選択されてしまわないこと
- [ ] 確定直後に候補ドロップダウンが「アニー / アニビア」で開くこと
- [ ] 変換中のEscapeがIMEの変換取り消しとして働き、入力欄が空にならないこと
- [ ] 変換中に「候補 N件」がラベル行に表示されること
- [ ] Google日本語入力でも同じ結果になること
- [ ] BOTタブの4スロットでも同じ挙動になること（`ChampionPicker` 共用）

> 近似的な自動回帰は Playwright MCP の `browser_evaluate` で合成イベントを発火して行える
> （`compositionstart` 後に `isComposing: true` の Enter を送り、選択が発生しないことを確認）。
> ただしOSのIMEウィンドウ描画は再現できないため、重なりの確認は目視に限る。
